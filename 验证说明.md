## English

### Table copy

Reproduction used a generic three-column Markdown table that contained inline formulas. In 0.4.4, selecting the table cells and pressing Ctrl+C copied one flat string with no row or column separators. `Range.cloneContents()` omitted the shared `TABLE` ancestor, so the converter received bare `THEAD` / `TBODY` / `TD` nodes and joined them as plain text. The compact context menu also called `Range.toString()`, which concatenated hidden formula source with the preview text.

0.4.5 restores the ancestor structure of a cross-cell selection, then runs that fragment through the existing Markdown converter. Ctrl+C and the menu copy share that path. A partial text selection inside a single cell stays plain text. Selecting only data rows adds an empty header. A partial row keeps column positions with empty cells and leaves unselected text behind.

The clipboard carries both Markdown text and a separate HTML table. The HTML drops editor controls, hidden source, and KaTeX layout nodes, and keeps rows, columns, and inline formatting. Formulas stay as LaTeX text with dollar delimiters, so pasting back into the Markdown editor can rebuild them. This is not a conversion to a native Word equation. When the rich-text clipboard is unavailable, the copy falls back to the full Markdown table.

### Formula flash while typing

Reproduction used a generic paragraph that contained eight inline formulas. Instant-render typing rebuilt the paragraph preview, and the compatibility layer refreshed formulas after a 40 ms delay, so TeX flashed during input. A frame probe saw raw formula text on 108 of 266 sampled frames before the change, and on 0 of 282 sampled frames after it. Frame counts move with machine load and are not a score.

The refresh is now one microtask, applied before the next paint. Hidden source is kept. Only the preview is refreshed; formula contents stay as they are. The frame checks look for both unrendered TeX and a visible source `CODE` element, and cover continuous typing, browser IME composition and commit, undo/redo, and explicit formula editing. WYSIWYG inline formulas use CodeMirror. Instant render uses in-paragraph source. The checks cover both.

## 中文

### 表格复制

复现使用一份通用的三列 Markdown 表格，单元格里带有行内公式。这是为说明准备的示例，不是从私人文档里摘出的原文。0.4.4 中选中这些单元格并按 Ctrl+C 后，复制结果是一整段没有行列分隔的文字。原因是 `Range.cloneContents()` 不包含公共祖先 `TABLE`，原转换器收到裸的 `THEAD` / `TBODY` / `TD`，于是把内容拼接成普通文字。紧凑右键菜单还直接使用 `Range.toString()`，会把公式的隐藏源码和预览文字拼在一起。

0.4.5 在复制跨单元格选区时补齐选中片段的祖先结构，再通过现有 Markdown 转换器生成表格。Ctrl+C 和菜单复制共用这条路径。正文里只选中单个单元格的一部分文字时，仍按普通文字处理。只选择数据行时加入空表头。部分行通过空单元格保留列位置，不带出未选中的文字。

剪贴板同时提供 Markdown 文本和独立的 HTML 表格。HTML 去掉编辑器控件、隐藏源码和 KaTeX 布局节点，保留行列和行内格式。公式以带美元分隔符的 LaTeX 文本保留，粘回 Markdown 编辑器后可以重建公式。这里没有把它说成 Word 原生公式转换。富文本剪贴板不可用时，退回完整的 Markdown 表格。

### 输入段落时的公式闪烁

复现使用一段通用正文，其中包含八个行内公式。这是为说明准备的示例，不是从私人文档里摘出的原文。即时渲染模式输入会重新生成段落预览，原来的兼容层延后 40 ms 才刷新公式，因此输入过程中会短暂显示 TeX。修改前，复现探针在 266 个采样帧里看到 108 帧原始公式文字；修改后，同一类输入探针在 282 个采样帧里看到 0 帧原始公式文字。帧数随机器负载变化，不是性能评分。

现在改为合并到一个微任务，在下一次页面绘制前刷新待渲染公式。隐藏源码保留，只刷新预览，不改写公式内容。逐帧检查同时查看未渲染的 TeX 和可见的源码 `CODE`，并分别覆盖连续键入、浏览器输入法组合与提交、撤销重做，以及显式公式编辑。所见即所得模式的行内公式使用 CodeMirror，即时渲染模式使用段落内源码，两种交互都有覆盖。
